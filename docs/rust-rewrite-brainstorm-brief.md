# 头脑风暴任务：ark 平台的"基础能力插件化"与服务清单

## 你的角色
你是资深平台架构师。请与设计文档作者（我）头脑风暴：
**ark 平台应该把哪些基础能力开发成可发布的"平台服务插件"，供其它插件复用？**
以及**多插件共用时的隔离约定**。

D:\code\github\smart-ark-wt-rust-rewrite\docs\rust-rewrite-design.md

§7.7 定义插件模型与 PluginContext。请先读 §7.5、§7.6、§7.7、§7.12。）

## 用户的核心想法（brainstorm 的出发点）
1. ark 不只提供 HTTP/MCP/界面三组能力；**日志、HTTPS 请求、配置存储这类基础设施，
   也应该做成插件形态，通过 ark 平台发布出去，供其它插件使用**。
2. 所有基础能力都要**默认假设多个插件同时使用**，因此隔离是一等设计约束。
   用户给出的两个示例约定：
   - 日志默认打印插件名（每条日志自动带 `plugin=<plugin_id>` 字段）；
   - 配置参数默认以 `{插件名}.{变量名}` 命名空间存储，互不可见、互不覆盖。
3. 目标效果：任何插件（内置或第三方）安装后即可获得日志/配置/HTTP/存储等全套基础设施，
   不需要自己实现；同时一个插件的日志/配置/凭据不会污染另一个插件。
