# Rust 重写需求设计

## 目标

以 Rust workspace 重建 ark 运行时和 Code 渲染层，消除旧 TypeScript/Electron 实现中的契约漂移、
重复逻辑、巨型装配、事件重放竞态和 Studio 双 agent 问题，同时保留已验证的用户交互与 sidecar 浏览器能力。

## 范围

包含回合运行时、模型适配、工具、会话、HTTP/SSE、Code UI、子代理、skills、provider、工作区检查和
UI 自动化领域边界。不包含 Write/Connect/工作流、Playwright 内核与云端后端重写。

## 全局验收

- 对外 DTO 由 Rust 单一真源生成，生成物无漂移；可执行逻辑只有一处实现。
- 会话日志可恢复、可迁移；SSE 在并发追加下无订阅空窗；取消和异常均收敛到终态。
- `ark-agent` 是唯一决策循环；Studio 和子代理不创建第二个模型循环。
- 新能力通过端口和插件/模块边界接入，不在核心添加平台分支。

## 迁移策略

旧运行时与 Rust 运行时并行验证时，同一数据目录任一时刻只能有一个写者。迁移必须验证父子会话归属、
复制并校验后再切换、重建投影；失败时保留诊断并不产生半成品。具体里程碑和单项交付应继续拆为独立
需求设计，不能把实施计划、审查报告或交接记录放回 `docs/`。

## 待决项

桌面外壳选型、Playwright 长期归属、旧数据格式兼容范围、Write/Connect 产品边界、许可证与命名迁移
在对应需求启动前必须定案。
