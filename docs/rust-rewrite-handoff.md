## 五、请重点审查的 10 个问题

### 架构类
1. **§5.2 的依赖 DAG 是否自洽**：`ark-agent` 只依赖 `ark-ports`；`ark-studio` 只依赖
   `ark-ports::BackendProvider`。这个约束在 Rust 里能否真的用 `xtask lint-deps` 强制？
   有没有被忽略的隐式依赖（如 `ark-plugin` 同时依赖 http/ui/mcp 是否合理）？
2. **§7.5 三层模型（能力端口 / 平台服务插件 / 业务插件）是否过度设计**？
   哪些能力其实应该留在内核？（头脑风暴已建议 MCP 总线、UI 容器、权限、审计、事件主干
   必须留内核——请判断是否还有该留内核却被插件化的）
3. **§7.5.5 隔离约定是否可执行**：`plugin_id` 由宿主注入、manifest 无关闭开关——
   在 Rust 类型系统里如何保证"插件不能自报身份"？有没有绕过路径（如全局单例）？

### 插件与 MCP
4. **§7.5.2 插件互调**：进程内 `mcp.call(provider, tool, args)` 的深度限制（3 层）
   与循环检测是否足够？两个插件互相调用形成的死锁（A 等 B、B 等 A）如何处理？
5. **§7.6 MCP 服务端权限模型**：`ClientGrant` + 风险分级 + 敏感操作走宿主审批，
   是否能覆盖"IM 消息驱动的回合"（§7.13）这类间接调用？`confirm:true` 不可自证这条
   在实现上如何保证？

### 存储与一致性
6. **§7.4 会话目录即系统记录**：目录为真源 + SQLite 仅索引，在 `indexed_seq` 水位对账
   （§7.4.2）后是否真能闭合崩溃窗口？FTS 只索引"标题+首尾消息"是否会漏掉用户预期的搜索？
7. **§7.4.3 的 `subscribe` 原子性**：`SnapshotAndSubscribe` 在单 writer actor 内完成
   "定水位→读积压→注册实时"。慢客户端断开重连时，`since_seq` 补齐是否可能与
   压缩产生的 seq 空洞冲突？

### 配置与迁移
8. **§7.15 最小重启**：把"生效方式"写成类型级 `ReloadClass` 是否会大量污染配置结构？
   插件代码升级必须重启（v1 静态装配）是否会成为体验瓶颈？
9. **§9.0 写权限规则 + §9.3 回退**：并行期"同一目录只有一个写者"的 owner 切换流程
   是否真的可回退？回退时旧运行时从快照恢复，是否会丢失切换期间的新会话？
10. **§7.16 的 8 项补齐**（可撤销副作用、waterfall 拦截、运行时不变量、真实 tokenizer、DAP…）
    是否优先级合理？其中"可撤销副作用"（`Registration` → `EffectScope`）
    会影响已发布的插件接口语义版本，现在补是否来得及？

### 横切检视要点：高性能与高并发（本轮已补齐，请验证设计是否闭合）

上一位 agent 指出的三项缺口**本轮已闭环**，不再是“文档未定义”，但仍请审查方案本身是否成立：

- **全局事件与审计主干**：新增 §7.4.6。事件按 `thread_id` / `plugin_id` 分片路由，
  每个订阅者独立有界队列；安全审计由独立 `AuditWriter` 单写并等待 `fsync` ack，
  Operational 审计与普通 trace/log 分级，禁止共用阻塞队列。请重点判断过载策略与
  `SecurityCritical` fail-closed 边界是否合理。
- **SQLite 索引单写者**：§7.4.2 新增 `IndexProjector`，全进程只允许它持有写连接；
  元数据、FTS 与 `indexed_seq` 在同一事务提交，队列满时转持久 dirty set，启动对账兜底。
  请重点判断“事件已落盘、索引异步最终一致”的崩溃窗口是否真正闭合。
- **量化性能门禁**：§10.2 已补 agent 编排 p99、工具派发 p99、插件总线 p99、
  全局事件吞吐、审计 fsync p99、索引 delta 吞吐六项指标，与 §7.14.4 的承诺对齐。
  请判断阈值是否现实、测试是否能稳定复现，而不是再次指出“缺少阈值”。

## 八、如何验证文档（可复现）

以下 PowerShell 片段在 worktree 根目录**按顺序整体执行**（第 2 段复用第 1 段的 `$n`；5.1 / 7 均可）。

```powershell
Set-Location D:\code\github\smart-ark-wt-rust-rewrite
$doc = "docs\rust-rewrite-design.md"

# 1) 结构：标题文本不重复、章节编号不重复（最容易回归的一项）
$h = Select-String -Path $doc -Pattern '^#{2,4}\s' | ForEach-Object { $_.Line -replace '^#+\s*','' }
"headings: $($h.Count)"
$h | Group-Object | Where-Object Count -gt 1                 # 应为空
$t = Get-Content $doc -Raw -Encoding UTF8
$n = [regex]::Matches($t,'(?m)^#{2,4}\s+(\d+(?:\.\d+)*)\.?(?=\s|$)') |
     ForEach-Object { $_.Groups[1].Value }
$n | Group-Object | Where-Object Count -gt 1                 # 应为空

# 2) 交叉引用：每个 §x.y 都指向真实存在的章节
$have = $n | Sort-Object -Unique
$refs = [regex]::Matches($t,'§\s?(\d+(?:\.\d+){0,2})') |
        ForEach-Object { $_.Groups[1].Value } | Sort-Object -Unique
$refs | Where-Object { $have -notcontains $_ }               # 应为空

# 3) 规模与编码（ReadAllBytes 走进程 CWD，必须先 Resolve-Path，否则会读到主工作区同名路径）
(Get-Content $doc -Encoding UTF8).Count                       # 2425
$b = [System.IO.File]::ReadAllBytes((Resolve-Path $doc).Path)
$b[0..2] -join ','                                            # 35,32,115 = "# s"，不是 239,187,191

# 4) §2 的每个问题 ID 都要在 §8 有对策
$s2  = [regex]::Match($t,'(?s)## 2\..*?(?=## 3\.)').Value
$s8  = [regex]::Match($t,'(?s)## 8\..*?(?=## 9\.)').Value
$ids = [regex]::Matches($s2,'\b[CBS]-\d+\b') | ForEach-Object { $_.Value } | Sort-Object -Unique
$ids | Where-Object { $s8 -notmatch [regex]::Escape($_) }     # 应为空

# 4b) 反向：全文引用的 ID 都必须在 §2 里定义过（否则是失效引用）
$all = [regex]::Matches($t,'\b[CBS]-\d+\b') | ForEach-Object { $_.Value } | Sort-Object -Unique
$all | Where-Object { $ids -notcontains $_ }                  # 应为空
```
